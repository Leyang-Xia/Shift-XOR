# Shift-XOR

Shift-XOR storage-code experiments and a reusable C++17 codec library.

The maintained library supports arbitrary valid `(n,k)` Two-Tone shift matrices, systematic `[I; Φ]` layouts, non-systematic `k × k` systems, arbitrary `k`-row survivor selection, scalar execution, and an optional AVX2 backend.

The implementation follows the Two-Tone subsequence extraction and elimination process described in Fu et al. The original standalone experiments remain under `legacy/` for historical comparison.

## Repository layout

- `include/shiftxor/` contains the public matrix, buffer, status, backend, and codec interfaces.
- `src/shiftxor/` contains matrix validation, Two-Tone elimination, scalar kernels, and the AVX2 kernel.
- `bench/` contains the JSONL benchmark CLI and optional ISA-L and Longhair adapters.
- `examples/` contains maintained examples built on the public API.
- `tests/` contains matrix, codec, backend, benchmark, example, and multi-parameter round-trip tests.
- `legacy/` contains the earlier fixed-parameter and LRC experiments.
- `docs/benchmark-methodology.md` describes benchmark denominators and external dependencies.

## Build

The default build uses CMake and enables AVX2 when the compiler supports it.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
```

For a portable scalar build that excludes AVX2-only legacy programs, use:

```bash
cmake -S . -B build-scalar \
  -DCMAKE_BUILD_TYPE=Debug \
  -DSHIFT_XOR_ENABLE_AVX2=OFF \
  -DSHIFT_XOR_BUILD_LEGACY=ON
cmake --build build-scalar -j2
```

To build only the maintained library and tests, set `SHIFT_XOR_BUILD_LEGACY=OFF`.

## Run tests

```bash
ctest --test-dir build --output-on-failure
```

The round-trip suite covers `(3,2)`, `(5,3)`, `(8,6)`, `(9,6)`, `(11,8)`, and `(15,10)` with multiple survivor selections. It checks 32-bit, 64-bit, and 256-bit slice widths and compares every decoded byte with the original input.

## Public codec API

A matrix entry is a non-negative shift count or `ShiftMatrix::kInfinity` for `z^∞`. The shift count is measured in configured slices.

```cpp
#include "shiftxor/codec.h"
#include "shiftxor/matrix.h"

using namespace shiftxor;

const auto matrix = ShiftMatrix::create(
    rows, columns, shifts_row_major);
const auto codec = ShiftXorCodec::create(
    matrix.value(),
    CodecConfig{input_length, slice_bytes, BackendKind::kScalar});

codec.value().encode(data_blocks, codeword_blocks);
codec.value().decode(survivor_blocks, decoded_data_blocks);
```

`ShiftMatrix::make_systematic_two_tone(n, k)` creates the reflected Two-Tone systematic matrix used by the default examples. `ShiftMatrix::create(...)` accepts user-supplied matrices. Decode validates the Two-Tone row-difference and divide conditions before running elimination. Non-Two-Tone matrices can still be encoded, but decode returns `kUnsupported`.

The decoder accepts exactly `k` unique indexed survivor blocks. Systematic codes first substitute available systematic sequences and then decode the missing columns from the selected parity submatrix. Non-systematic codes extract the paper-defined `\hat{x}_u` subsequences and solve the dependency graph generated by Two-Tone elimination.

## Slice widths and AVX2

`slice_bytes` controls the physical unit of a matrix shift.

- `slice_bytes = 4` means one shift moves 32 bits.
- `slice_bytes = 8` means one shift moves 64 bits.
- `slice_bytes = 32` means one shift moves 256 bits, matching one AVX2 register.

All three choices are valid for encoding and decoding. The current AVX2 kernel directly uses 32-byte XOR operations when a call covers at least 32 bytes with aligned offsets. With 4-byte or 8-byte slices, the current per-slice calls use the scalar fallback. A future throughput optimization can batch adjacent slices into 32-byte AVX2 operations without changing the matrix shift unit.

## Benchmark

The benchmark emits one JSON object per operation and codec.

```bash
build/bin/shiftxor_bench \
  --n 9 --k 6 \
  --bytes 1048576 \
  --slice 8 \
  --iterations 10 \
  --backend scalar \
  --codec all \
  --format jsonl
```

Default cases are `(9,6)`, `(15,10)`, `(18,12)`, and `(20,16)`. Records include logical input bytes, physical stored bytes, elapsed time, throughput, dependency availability, and decoded-data validation.

## ISA-L and Longhair adapters

Both adapters are optional. They are reported as unavailable when their dependencies are absent.

```bash
cmake -S . -B build-external \
  -DSHIFT_XOR_ENABLE_ISAL=ON \
  -DSHIFT_XOR_ENABLE_LONGHAIR=ON \
  -DISA_L_ROOT=/path/to/isa-l \
  -DLONGHAIR_ROOT=/path/to/longhair
cmake --build build-external -j2
```

The ISA-L adapter uses its GF(2^8) erasure-code API. The Longhair adapter uses its Cauchy Reed-Solomon API. The benchmark keeps their logical-byte denominator consistent with Shift-XOR and reports physical storage separately.

## Legacy experiments

The old fixed-parameter programs and LRC experiments are isolated under `legacy/`. They remain available as separate targets when `SHIFT_XOR_BUILD_LEGACY=ON`. CMake generates the historical `dummy.txt` input in the build root and `bin/` so the legacy programs can run from their normal build locations.

The maintained `(9,6)` example uses the new API.

```bash
build/bin/shift_xor_9_6
```
